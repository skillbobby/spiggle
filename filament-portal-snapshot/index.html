Features

Everything an operator needs around a dump

High-speed database snapshots designed natively for Filament panels with automated schedules, safety rails, notifications, and remote copies.

Create on demand

Name a dump, pick a connection, optionally limit or exclude tables, and compress to .sql.gz. Execution runs on background queues.

Restore with a confirm phrase

Type RESTORE before tables drop. Restores are strictly blocked outside allowed environments so production stays safe by default.

Golden baseline

Star one snapshot as the known-good demo state. Nightly schedules can always load that file while newer dumps keep accumulating.

Automated schedules

Create, restore, remote-copy, or clean up on midnight, daily, hourly, weekly, every six hours, or with custom cron syntax.

Export & remote storage

Download dumps directly from the panel. Copy automatically to any Laravel disk — AWS S3, Google Cloud Storage, SFTP, or Google Drive.

Bell + inbox alerts

Completions land in the Filament notification bell and an asynchronous email. Mail fails gracefully if it is not configured.

Plugin tables survive restore

Schedule rows and operation audit records are preserved across a database restore so the plugin does not wipe its own history.

Detailed activity log

Every create, restore, export, cleanup, and remote copy is recorded with execution status, actor username, duration, and output messages.

Nightly Reset

Put the portal back how you left it, every night

The reason this plugin exists: run a public demo environment that visitors can test and modify, then effortlessly revert to a pristine baseline at midnight.

1

Capture the Baseline

Once your demo portal is seeded and formatted to perfection, create a snapshot named demo-baseline and click the star icon to designate it golden.

2

Schedule the Restore

Create a schedule: Action: Restore Snapshot. Frequency: Every night at 00:00. Toggle on “Restore the golden snapshot”.

3

Leave the Scheduler Running

Standard Laravel scheduler runs portal-snapshot:run-schedules each minute. Completed resets and any warnings hit the notification bell and email.

Installation

Free Community Release

Portal Snapshot is 100% free and open-source for the Filament & Laravel community. Install via Composer, publish config, and star the repository to support ongoing development.

Panel Registration

Register the plugin inside your Filament Panel Provider (e.g. AdminPanelProvider.php). Authorize specific roles and assign navigation options.

use Spiggle\FilamentPortalSnapshot\FilamentPortalSnapshotPlugin;

public function panel(Panel $panel): Panel
{
  return $panel
    ->plugins([
      FilamentPortalSnapshotPlugin::make()
        ->authorize(fn () => auth()->user()?->is_admin ?? false)
        ->navigationGroup('Portal Operations')
        ->navigationSort(10),
    ]);
}

Setup Checklist

  1. Add a snapshots disk configuration in config/filesystems.php.
  2. Publish configuration and migrations: php artisan vendor:publish, then migrate.
  3. Ensure a queue worker is running and crontab executes * * * * * php artisan schedule:run.
  4. Optionally enable remote disks (AWS S3, Google Drive, SFTP) and notification emails in config.

FAQ

Frequently asked questions

Quick answers to common questions about features, compatibility, and licensing.

Is this plugin really free to use?

Yes! Portal Snapshot is released as a free community package for personal, commercial, and client projects. If it adds value to your projects, starring the repository on GitHub and following along on X helps us continue to build and maintain open-source Laravel tools.

What does this plugin do?

It provides a native Filament UI and scheduling engine for database snapshots. Operators can create, download, copy remotely, delete, and restore dumps — and schedule those same actions, including an automated nightly demo reset against a golden baseline.

Which Filament and Laravel versions are supported?

Filament 4 and Filament 5. Fully compatible with PHP 8.2+ and Laravel 11, 12, or 13.

Is restore allowed in production environments?

Not by default. Restores are strictly blocked unless your current environment is explicitly listed in filament-portal-snapshot.allow_restore_environments (defaults to ['local', 'staging', 'demo']). Additionally, operators must type the confirmation phrase RESTORE before any tables are altered.

What happens if mail is not configured?

The queued email notification is safely skipped and logged at the debug level without interrupting operations. Database notifications in the Filament bell still fire immediately.

How does remote replication (AWS S3, Google Drive, SFTP) work?

Point filament-portal-snapshot.remote.disks to any disk configured in your Laravel config/filesystems.php. The plugin streams the compressed snapshot file directly using Laravel’s Flysystem abstraction.
